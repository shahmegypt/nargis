# النرجس — دليل الأنشطة والعروض المحلية

تطبيق ويب عربي RTL لاكتشاف الأنشطة والعروض في النرجس 1 والنرجس 2. الصيانة مساحة خاصة وثانوية. الواجهة ما زالت محلية ولم تُنشر بعد. طُبقت ترحيلات قاعدة البيانات على مشروع Supabase المتصل ونُشرت وظيفة Web Push، وتحتاج مفاتيحها السرية وربط Webhook قبل إرسال الإشعارات للأجهزة.

## تشغيل المعاينة

```bash
npm install
npm run dev
```

من دون متغيرات Supabase، يعمل التطبيق ببيانات عرض محلية داخل المتصفح. هذه ليست حسابات أو طلبات مشتركة ولا تحفظ على الخادم.

## Supabase

1. أضف إلى `.env.local`:

   ```dotenv
   VITE_SUPABASE_URL=https://<project-ref>.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=<publishable-key>
   ```

2. طبّق كل الملفات في `supabase/migrations` باستخدام Supabase CLI بعد ربط المشروع. الترحيل الأحدث يفعّل حدودًا جغرافية فعلية؛ لن يقبل قاعدة البيانات اعتماد نشاط تجاري حتى يحفظ المدير حدود GeoJSON الصحيحة للنرجس 1 والنرجس 2 من إعدادات الإدارة.
3. احصل على مضلعات GeoJSON موثوقة من مصدر خرائط/مساحة معتمد. من لوحة الإدارة الصق Geometry من نوع `Polygon` أو `MultiPolygon` لكل منطقة. لا تستخدم إحداثيات تقديرية. بعد حفظ المضلع، يجب على مشرف الأنشطة أيضًا مراجعة دبوس المنشأة وموقع المحل قبل الاعتماد.
4. اضبط تسجيل الدخول برمز SMS وحدود الإرسال لدى Supabase Auth. أنشئ أول مدير رئيسي بعد إنشاء حسابه، من SQL Editor:

   ```sql
   insert into public.user_roles (user_id, role_id)
   select '<AUTH_USER_UUID>', id from public.roles where role_key = 'admin'
   on conflict do nothing;
   ```

   المدير يراجع عنوان السكن الذي يرسله المستخدم. يلزم اعتماد هذا العنوان قبل تمكين بلاغات الصيانة. أدوار الإدارة وتغييرات الحسابات والقرارات تسجل في سجل التدقيق.

5. صور النشاط والإعلان تحفظ في bucket خاص. يرسل التطبيق روابط موقعة مؤقتة بعد التحقق من حالة النشاط وصلاحية المستخدم؛ الطلبات المعلقة لا تحصل على رابط عام دائم.

لا تضع `service_role` في الواجهة أو أي متغير يبدأ بـ `VITE_`.

## دعم Grok

- يمر طلب الدعم عبر `/api/customer-support` ومفتاح xAI محفوظ في الخادم فقط.
- endpoint يتحقق من جلسة Supabase، ثم يطبق حدًا ذريًا لكل حساب: 20 طلبًا يوميًا مع فاصل 6 ثوانٍ قبل استدعاء Grok. يلزم تعيين `GROK_API_KEY` و`SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` في إعدادات بيئة Cloudflare Pages. لا تضع هذه القيم في المحادثة.
- محليًا، أضف `GROK_API_KEY` إلى `.env.local`. يستعمل خادم Vite قيم `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` للتحقق من الجلسة. يتطلب ذلك ربط Supabase وتسجيل الدخول.
- أضف `GROK_MODEL` اختياريًا لتغيير النموذج. تكلفة Grok تعتمد على حساب xAI واستخدامه.
- رسائل المساعد لا تحفظ في قاعدة بيانات النرجس، لكنها ترسل إلى xAI لمعالجة الرد. لا ترسل أسرارًا أو بيانات سكن في المحادثة.

## الإشعارات حتى عند إغلاق التطبيق

يسجل المتصفح الاشتراك ويعرض الإشعار الوارد عبر Service Worker. تضيف قاعدة البيانات إشعارًا داخل التطبيق عند اعتماد أو تغيير حالة نشاط/إعلان/بلاغ. لإرسال Web Push الفعلي:

1. أنشئ زوج مفاتيح VAPID واحفظ العام في `VITE_VAPID_PUBLIC_KEY` والخاص في أسرار الخادم فقط.
2. انشر `supabase/functions/send-web-push` إلى Supabase Functions بعد ضبط أسرار `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` و`VAPID_SUBJECT` و`PUSH_DISPATCH_SECRET`. لا تضع المفتاح الخاص أو سر التوزيع في المتصفح.
3. أنشئ Database Webhook على جدول `public.user_notifications` عند `INSERT`، ووجّهه إلى وظيفة `send-web-push`. أرسل `x-nargis-push-secret` بقيمة `PUSH_DISPATCH_SECRET`. الوظيفة تتحقق من الحدث، وتزيل اشتراكات الأجهزة المنتهية عند استجابة 404 أو 410.

الإشعارات داخل التطبيق لا تتطلب إرسال Push. مزود رسائل SMS وxAI قد يفرضان تكلفة حسب الإعداد والاستخدام.

## Cloudflare Pages

اربط مستودع GitHub واضبط أمر البناء `npm run build` ومجلد الإخراج `dist`. أضف مفاتيح Grok وSupabase الخادمية المذكورة في إعدادات Pages Functions، ومفاتيح الواجهة `VITE_*` ضمن متغيرات البناء. لا تنشر قبل إضافة مضلعات الحدود ومراجعة إعداد SMS وVAPID وWebhook.

## ما توفره الشيفرة الآن

- بحث وفلاتر للفئة والمنطقة والترتيب، وصفحات دليل بتحميل تدريجي.
- ملفات أنشطة وعروض متعددة الصور، وتعديل الملف يعيده للمراجعة؛ الإعلان المعتمد يمكن إيقافه مؤقتًا.
- تحقق جغرافي على قاعدة البيانات عند اعتماد الأنشطة التجارية بمجرد ضبط الحدود الرسمية.
- خصوصية تقييمات السكان والبلاغات، مع ربط بلاغ الصيانة بعنوان سكن يراجعه المدير.
- أدوار جاهزة قابلة للإسناد، إدارة حالة الحساب، تحليلات مشاهدات مسجلة للحسابات، وسجل تدقيق للإجراءات.
- سياسات إصدار 1.2 كاملة من قاعدة البيانات، موافقتها شرط التسجيل، ويعاد طلب الموافقة عند تغير النسخة المطلوبة.
- صندوق إشعارات داخل التطبيق ومرسل Web Push جاهز للربط بقاعدة البيانات.
